### 1.2 有意不还原的部分（合规边界）

原型 `AGENT_HANDOFF_TEXT`（第 167–183 行）描述了一套**违规能力清单**。逐条对照：

| 原型描述的能力 | 处置 | 原因 |
|---|---|---|
| preload 覆写 `document.visibilityState` 恒为 `visible` 并拦截 `blur`/`visibilitychange` | **不实现** | 反检测规避手段，属平台反自动化对抗 |
| `MutationObserver` 捕获随堂测验弹窗 → DeepSeek → `Input.dispatchMouseEvent` 自动点击关闭 | **不实现** | 无人值守自动答题 |
| 本地 `tesseract.js` OCR + 自动勾选答案 | **不实现** | 同上 |
| GCJ-02→WGS-84 转换 + **±5 米随机偏移防止同学坐标雷同** + 静默定位签到 | **不实现** | 位置伪造 + 明确以规避查重为目的 |
| `electron-updater` + GitHub Releases 开机静默自动更新 | **不实现** | 首版不做自动更新 |

> 结论：**视觉语言完整还原，能力边界按需求重新划定**。
> 原型的假数据（`accountStatus` 全平台预登录、`progress` 定时器伪造进度、
> `activities` 假日志、`handleCheckInNow` 假签到、`apiTestStatus:'connected'` 假连接）
> 全部替换为真实状态或明确空态。

> **截图方法学说明（重要）**：Playwright 的 `win.screenshot()` 只截 renderer 的 web 内容，
> Electron 的 `win.capturePage()` 截的是窗口 web contents，**两者都不含原生 WebContentsView**。
> 若只用这两种方法，会误判「平台网页/视频/地图没渲染」并去做错误的「修复」。
> 因此 `screen-*.png` 一律用 PowerShell + .NET 的 OS 级屏幕捕获，
> 这才是用户实际看到的画面。
